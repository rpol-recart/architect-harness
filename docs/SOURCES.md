# Методологические и технические источники

Список проверен при подготовке проекта 6 ноября 2026 года. Это источники подходов, а не доказательство работоспособности данной реализации. Формулировки рабочего каталога — адаптация для этого харнесса; чужие вопросники и книжные главы не копируются целиком.

| Источник | Использование в проекте | Предел применимости |
|---|---|---|
| [Cervantes, Kazman — Designing Software Architectures, 2nd edition, 2024](https://www.informit.com/store/designing-software-architectures-a-practical-approach-9780138108021) | ADD 3.0: цель итерации, выбор элементов для уточнения, альтернативы, обязанности, интерфейсы и оценка результата | Метод не выбирает автоматически единственную правильную архитектуру |
| [arc42 Method](https://arc42.org/method/) | Связь требований, структуры, сквозных механизмов, обсуждения и реализации | Рабочая процедура требует адаптации к масштабу и риску проекта |
| [arc42 Building Block View](https://docs.arc42.org/section-5/) | Постепенное раскрытие узлов и привязки архитектурных блоков к коду | Статический вид дополняется сценариями исполнения |
| [SEI — Maintainability, 2020](https://www.sei.cmu.edu/library/maintainability/) | Вопросы о границах, зависимостях, изменяемости; связь ответа с реализацией, предположениями и риском | Рассматривает сопровождаемость; другие качества требуют своих вопросов |
| [SEI — Early Analysis of Software Architecture](https://www.sei.cmu.edu/library/early-analysis-of-software-architecture/) | Анализ качественных требований и достаточности сведений для архитектурного вывода | Анализ модели не заменяет исследование исполняемой системы |
| [SEI — Quality Attribute Workshop](https://www.sei.cmu.edu/library/quality-attribute-workshop-collection/) | Выявление значимых сценариев и требований до детализации архитектуры | Сценарий требования не является наблюдением |
| [George Fairbanks — Risk-Driven Model](https://www.georgefairbanks.com/software-architecture/risk-driven-model/) | Выбор глубины исследования и условие завершения по существенности рисков | Оценка риска зависит от конкретного проекта и доступных сведений |
| [Cosmic Python — Architecture Patterns with Python](https://www.cosmicpython.com/book/preface) | Прикладные вопросы о бизнес-логике, инфраструктуре, согласованности и зависимостях | Книга ориентирована на TDD, DDD и события; эти практики не объявляются обязательными |
| [Cosmic Python — Repository Pattern](https://www.cosmicpython.com/book/chapter_02_repository) | Рассмотрение стоимости дополнительной абстракции и применимости к CRUD | Наличие слоя само по себе не является критерием качества |
| [Cosmic Python — Epilogue](https://www.cosmicpython.com/book/epilogue_1_how_to_get_there_from_here) | Начало работы с существующим кодом с конкретной проблемы и постепенного разделения обязанностей | Учебные примеры требуют адаптации к промышленному окружению |
| [Python — Developing with asyncio](https://docs.python.org/3/library/asyncio-dev.html) | Вопросы о блокирующих операциях, задачах и ошибках асинхронного исполнения | Проверять применимость к версии Python и библиотекам проекта |
| [PyPA — src layout vs flat layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/) | Различие исходников, установленного пакета и условий запуска | Конкретный layout не является обязательным архитектурным правилом |
| [Cervantes, Kazman, Cai — LLM-assisted ADD, 2025](https://arxiv.org/abs/2506.22688) | Явная процедура, итерации и сохраняемое описание архитектуры в работе человека с LLM | Оценка на кейсах не доказывает надёжность автономной промышленной эксплуатации |
| [MCP Architecture](https://modelcontextprotocol.io/docs/learn/architecture) | Граница между хостом, клиентом и сервером | MCP не определяет политику архитектурных решений приложения |
| [Официальный MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) | Реализация протокольного адаптера и проверка клиентского взаимодействия | Версия SDK и протокола должна согласовываться с целевым хостом |

## Что является собственной проектной адаптацией

Типы узлов и связей v0.1, форма пакета изменений, политика рассмотрения, поля происхождения свидетельств, каталог условий применимости вопросов и схема сборки контекста определены для этого проекта. Они не выдаются за нормативную часть ADD, arc42 или MCP.
